# biobank-agent v3.1-RC Roadmap — The Capability-Acquisition Layer

> Chief-architect synthesis of a first-principles multi-agent brainstorm (6 framework surveys —
> Codex, Hermes, OpenCode, gemini-cli, claw-code, DeepSeek-TUI, LangChain/LangGraph/LangSmith/
> LangFlow/Dify; a CKB/UKB domain paper + skill-cluster taxonomy; 4 persona roadmaps — PM / agentic
> engineer / computer scientist / bio scientist; and an adversarial Skeptic + Integrator critique).
> v3.1-RC builds **on top of** the shipped v3 milestones **M0–M9** (lazy manifest, DataProbe, evidence
> contract, methodology reviewer, scheduler backends, robust council, durable rollout, receipts,
> self-evolution gate, usage curator). It does **not** re-propose them.
>
> **Every code claim below was re-verified against the live tree on `main`.** Notable verifications:
> `manifest.json` is a flat two-level map (`domains` → `[names]`, `summaries` → one-liner); `manifest.py`
> `_load()` fails safe to `{}` → all-DIRECT; `runtime/methodology.py:review_methodology` is tabular-only
> and has exactly **one** caller (`skills/statistical_review.py`) and is **absent** from
> `runtime/completion.py`; `runtime/self_evolve.py:apply_patch_transactionally` gates patches in a
> throwaway worktree with `DEFAULT_APPLY_ALLOW_PATHS` incl. `custom_skills/` and never auto-merges a
> `PROTECTED_PREFIXES` path; `runtime/patch_generation.py:generate_patch_for_proposal` +
> `runtime/evolution.py:EvolutionProposal{target_path,diff,test_commands}` exist; `council.py` exposes
> `run_one`/`run_parallel`/`map_parallel` and `planner.py` exposes `_debate/_prune/_converged/_similarity/_merge/_critique`
> with `_DRAFT_ROLES = [PLANNER, PRIMARY_EXECUTOR, CRITIC]` and a single symmetric `_revise_messages`.
>
> **Two corrections to roadmap folklore, both load-bearing:**
> 1. **`discover_custom_skills` is an execution surface.** `registry.py:345` calls
>    `spec.loader.exec_module(mod)` on every `*.py` in `custom_skills/` at agent boot (`agent.py:211`)
>    with **no** `SkillGenerator.validate_code` at load time. The claim that ingestion "adds zero new
>    execution risk because the apply gate covers everything" is **false** — the gate only runs
>    `test_commands` in a worktree; ingested module bodies/decorators run with full privileges on the
>    next boot after a human merges. The auto-code-execution contract (§7) closes this.
> 2. **`wgs_environment_check` is not a defined `@skill`.** It appears only in `planner.py` scaffolds
>    and manifest domain lists. `utils/wgs.py` provides the *primitives* (`package_available`,
>    `find_executable`, `command_supported`). `sc_method_environment_check` must be built on those, not
>    on a non-existent skill.

## 1. North Star

v3 made biobank-agent a **trustworthy instrument** (every "done" bound to a real, methodology-checked,
re-runnable artifact). **v3.1-RC makes it a *capability-acquiring* instrument**: a CKB/UKB scientist can
hand it a method paper or a GitHub skill-library URL and, within minutes, run a **new**,
contract-checked, reproducible analysis on their own spatial / single-cell / post-GWAS / somatic data
that they'd otherwise spend a week wiring.

The killer demo: point it at `github.com/fym0503/stereo-seq-skills`, drop a Stereo-seq `h5ad`, and watch
it auto-classify the corpus into the **SPATIAL** branch, env-gate the heavy deps, run
`spatial_domain_discovery` behind a PRE/POST **method contract** the M3 reviewer enforces, and emit an
M7 receipt. **Capability the notebook cannot cheaply match is the moat.** The council/measurement work
is intelligence polish that only earns its slot once the corpus can actually grow.

## 2. Design Principles (first-principles tenets)

1. **Context cost scales with the depth you WALK, not the corpus you OWN.** A flat list of *N* skills
   costs *O(N)* summary tokens and gives ≈log₂(N) bits of disambiguation per search; a balanced tree
   costs *O(branching)* tokens per navigation step and yields ≈log₂(branching) bits *per level*. The
   model pays for depth only along the path it walks. This is why the tree is the v3.1-RC foundation.
2. **One trust kernel, many front-ends.** `apply_patch_transactionally` is the *single* chokepoint.
   Paper-synthesis (a), external ingestion (b), and any future frontier crawl (e) are front-ends that
   *emit* a gated `{target_path, diff, test_commands}` + method contract into that one gate and self-file
   via `classify_skill`. **There must never be a second approval path** (no ad-hoc `importlib`
   hot-loading, no parallel sandbox).
3. **Auto-acquired code is untrusted until proven, at LOAD time as well as APPLY time.** The worktree
   gate proves *behavior*; it does not stop module-body execution on the next boot. External/synthesized
   skills get a load-time AST gate, shell-out-only adapters, and an explicit per-corpus human enable.
4. **Method contracts over return codes — for omics, not just tabular GWAS.** Pseudoreplicated DE,
   batch-confounded clustering, velocity from connectivity, spatial enrichment with no permutation null,
   coloc on un-harmonized alleles: each is *garbage-but-green*. The M3 reviewer must learn these sins and
   gate goal-acceptance on them, or scaling the corpus scales silent wrongness.
5. **Demand-driven, never daemon-driven.** A scientist pointing at a specific paper IS the quality
   gate. An always-on crawler manufactures supply with no demand signal and normalizes auto-merge of
   LLM-synthesized analysis code — the exact thing the M8 review-branch discipline exists to prevent.
6. **Reuse the hardened core; wire, don't rebuild.** No MCP daemon, no Effect-style ServiceLayer
   rewrite, no async Scheduler/state-machine in v3.1-RC — those touch `PROTECTED_PREFIXES` and deliver zero
   scientific capability. Ingestion gives goal-b ≈90% of MCP's value through the already-hardened gate.
7. **Demote, never delete; hard-fail, never fake.** The descriptive multiomics skills become a labeled
   `MULTIOMICS_PREVIEW` "data-not-ready glance" tier the M1 DataProbe selects — *never* a silent
   fallback when scanpy/squidpy is missing. Every heavy engine hard-fails loudly via
   `sc_method_environment_check`.
8. **Measurable or it didn't happen.** "More capable" is a number on real work (online eval over
   sampled live turns + an A/B harness), not a vibe.

> **Implementation status (v3.1-rc branch).** M10–M16 are implemented, tested, and committed.

## 5. Multi-Agent Intelligence Engine (goal-d)

**The gap (verified):** the council *already* does bounded multi-round debate with confidence-pruning +
a consensus short-circuit over `run_parallel`, and every candidate already carries a 0–100 critic score
(`_critique`) that `_prune` and `_merge` consume. But the debate is **symmetric** — every agent runs the
same `_revise_messages` prompt — and `ProviderRole` has `PLANNER`/`CRITIC`/`SAFETY_REVIEWER` that the
debate never uses asymmetrically. A symmetric agreement-seeking mechanism provably converges to the
*mean* opinion, not the *correct* one: it improves coherence but cannot stress-test a plan because no
agent is *incentivized to attack*.

**The mechanism (M16), from mechanism design + LangGraph Send/Command:** add `runtime/debate_game.py`
*layered on the existing primitives* (no graph engine).

- **Roles (asymmetric):** *proposer* (`PLANNER`, drafts as today); *adversary* (`CRITIC`, prompted to
  construct the **single highest-impact methodological failure case** against a *specific* candidate,
  **seeded with M11's omics-sin catalog** so it stress-tests "cluster then DE across all cells"); *referee*
  (`SAFETY_REVIEWER`, scoring each proposer plan **after** seeing the attack).
- **Payoff:** `payoff = base_quality − successful_attacks + successful_defenses`, folded **into the
  existing `node['score']`/`node['confidence']` channel** so `_prune`/`_converged`/`_similarity` and the
  budget/cancel guards stay **verbatim** and `_merge` automatically favors attack-survivors.
- **Send-style fan-out:** one adversary job per *surviving* candidate, sized from state — exactly
  `map_parallel`'s existing pattern.
- **Command-style hops:** a small Python dispatcher returning `'escalate' | 'merge' | 'reround'`,
  consumed by `_debate`'s existing loop.
- **Observability:** emit `adversary`/`referee` as new `persona_tags` so the live dashboard shows the game.
- **Gate:** behind `config.enable_adversarial_debate` (symmetric stays the default fallback) **plus** an
  A/B harness case — if game-mode plans don't beat symmetric on a held-out methodology-sin set (ideally
  M11's catalog), it stays off. M15's online eval supplies the live A/B number.

This is **intelligence polish, not a capability unlock** — sequenced last among the build set.

## 6. Skill-Acquisition Engine (goals a + b + c; e explicitly declined)

The unifying picture: **the tree is the destination, the contract is the rejection oracle, the apply
gate is the one chokepoint, and `classify_skill` is the filing clerk.** Synthesis (a) and ingestion (b)
are the two front-ends; both produce a gated proposal, never code that runs before the gate.

```
                          ┌─────────────────────────────────────────────┐
  paper (doi/path) ──▶ skill_from_paper (M12) ─┐                         │
  github url ────────▶ skill_ingest    (M14) ──┤                         │
                                               ▼                         │
                               MethodContract (M11 dataclass)            │
                                               │ review_methodology  ◀── M11 omics sins
                                               │ (HARD-BLOCK a sin BEFORE generation)
                                               ▼                         │
                         EvolutionProposal{target_path,diff,test_commands}
                                               │ generate_patch_for_proposal (exists)
                                               ▼                         │
                       apply_patch_transactionally  ◀── ONE trust kernel │
                       (worktree + mutation_check + allow-list,          │
                        external code → review_branch, NEVER auto-merge) │
                                               │ on pass                 │
                                               ▼                         │
                          classify_skill (M10) ─▶ files into the tree    │
                                               │  (trust='external'+source_url provenance)
                                               ▼                         │
                          discover_custom_skills  ◀── validate_code HARD load gate (M13)
                          (only after explicit per-corpus human enable)  │
                          └─────────────────────────────────────────────┘
```

### Hierarchical tree (goal-c, M10)

Extend `manifest.json` with a `tree` block (`{node_id, parent, summary, children, skills[]}`) carrying
the TREE PROPOSAL nodes: `genomics_germline > statgen_postgwas`; `genomics_somatic`;
`singlecell > {sc_core, sc_dynamics, sc_regulation}`; `spatial > {spatial_core, spatial_composition}`;
`genetics_x_cell`; `methodology > method_contracts`; `multiomics_preview` (the demoted descriptive
skills). New file `skills/skill_tree.py`: `navigate_tree(node_id)` returns children + one-line summaries +
leaf skills (mirrors `skill_search`'s deferred-load UX so **one** level enters context per turn);
`classify_skill(name, description)` picks the best leaf via the CRITIC `ProviderRole` through
`council.run_one`, **falling back deterministically to `registry.search` token-overlap** when the model
is unavailable (offline/unit-test). `manifest.py` gains `tree_of`/`children_of`/`node_summary` +
`invalidate_tree_cache()` and **degrades to today's all-DIRECT view if the `tree` key is absent/malformed**
(preserve the `_load()` fail-safe). The engine's flat `category_summaries()` injection is replaced by a
top-level tree-node summary list + a native `navigate_skill_tree` tool; `registry.search` gains an
optional subtree filter. New heavy domains are all `exposure='deferred'`; descriptive multiomics skills
drop to a `preview` role.

### Skill-from-paper synthesis (goal-a, M12)

`runtime/skill_from_paper.py` reuses `EvolutionProposal` end-to-end. A subagent runs
`deep_research`/`read_paper` (all four paper skills exist), then a method-extraction prompt produces a
`MethodContract {inputs, outputs, preconditions, postconditions, statistical_assumptions, citation}`.
**Before** generation, `review_methodology(contract)` HARD-BLOCKs a consensus sin (no multiple-testing
correction, n below power, missing CI, *or* an M11 omics sin). The contract is embedded as
`proposal.summary` + `evidence` and `generate_patch_for_proposal` emits a new `custom_skills/` `@skill`
whose **docstring IS the contract** and whose co-located pytest asserts the postconditions **on a tiny
synthetic JSON fixture, WITHOUT importing the heavy lib** (see §7 gate-test rule). Route through
`apply_proposal` (always review-branch for agent-authored analysis logic) → `classify_skill`.
**ROI honesty:** an LLM extracting a runnable method + a *non-vacuous* postcondition test from prose is
the least reliable step; `patch_generation.py` itself notes a vacuous `assert True` would pass. Ship it
review-branch-only and measure accept rate on ONE real skill (e.g. C1 `sc_qc_preprocess`) before scaling.

### External skill-library ingestion (goal-b, M14)

`skills/skill_pkg.py` defines a Dify-style `SKILL_PACKAGE.json`
(`{version, source_url, commit_sha, license, author, trust:'external', skills:[{name, description,
domain_hint, entrypoint, parameters, capabilities, requirements}]}`) — the *contract*, not the code, is
what makes a foreign corpus mergeable. `runtime/skill_ingest.py`: git-clone/tarball-fetch into a temp dir,
**reuse `self_evolve._normalize_under` + `DEFAULT_APPLY_ALLOW_PATHS`** so every file lands under
`custom_skills/<corpus>/` and nothing escapes, run `validate_code` on each entrypoint (per M13's widened
adapter lane), route the whole batch through `apply_patch_transactionally` (**one review-branch per
corpus — external code is NEVER auto-merged**), then write each accepted skill into `manifest.json` with
`trust='external'` + `source_url` and call `classify_skill`. Vendor `fym0503/stereo-seq-skills` (gitignored
under `custom_skills/`) as the first corpus with thin `spatial_*` adapters that **shell into its scripts
via `local_exec`** and normalize outputs to the evidence/result schema, each gated by
`sc_method_environment_check`. Surfaced as a hidden meta `@skill ingest_skill_library(url)` callable by
the **curator/operator, not the executor**. A `HubLockFile` (name, source, commit_sha, content_hash,
install_path) gives provenance + uninstall. **Scope discipline (Skeptic):** drop 462-digest mining and
heavy HubLockFile machinery from v3.1-RC scope (gold-plating); vendor exactly one corpus behind a flag.

### Goal-e (continuous frontier ingestion) — DECLINED in v3.1-RC

Both the PM and Engineer personas explicitly **AVOID** the autonomous crawler, and the Integrator's
convergence verdict is unanimous-by-implication: frontier ingestion **is** M12
(`synthesize_skill_from_paper`) triggered on-demand by a scientist pointing at a specific paper — that
human-in-the-loop trigger *is* the quality gate. An always-on subagent manufactures skill supply with no
demand signal, floods the tree/curator with low-precision noise, and risks normalizing auto-merge of
LLM-synthesized analysis code that the entire M8/review-branch discipline exists to prevent. Its only
defensible form (a thin curator scheduler calling the pull-based M12/M14 front-ends, all on
review-branches, default OFF) is a ~1-day add **after** M10–M16 ship and is **not** worth a roadmap slot
now. **Build the demand-driven version; refuse the daemon.**

## 7. Auto-Code-Execution Safety Contract (MANDATORY for M13/M14, and for any M12 shell adapter)

The single most dangerous claim in the brainstorm — "ingestion adds zero new execution risk" — is
**false** and is resolved here. The apply gate proves *behavior* in a worktree; it does **not** stop a
merged module's body/decorator code from executing on the next agent boot
(`discover_custom_skills` → `spec.loader.exec_module`, registry.py:345; `agent.py:211`).

1. **Load-time AST gate (the missing hard gate).** `discover_custom_skills` MUST call
   `SkillGenerator.validate_code` on every `*.py` **before** `exec_module`, refusing to load any file that
   fails. This makes the AST whitelist a *load-time* invariant, not just an apply-time one.
2. **A widened, explicit adapter-validation lane.** The current `ALLOWED_IMPORTS`
   (numpy/pandas/scipy/sklearn/xgboost/… — **no** `subprocess`, **no** `biobank_agent.skills.local_exec`)
   and `FORBIDDEN_CALLS` (`open/system/popen/call/run`) + the blanket private-attribute ban **reject every
   legitimate scanpy/squidpy adapter**. Resolve **in writing**: adapters are **shell-out only** — they
   import **no** heavy lib in-process and invoke the heavy tool **through the registered `local_exec`/
   `shell_exec` @skill seam** (already gated by `confirmed=` + write-policy). The adapter lane AST-allows a
   call to that seam specifically while **still forbidding raw `subprocess`/`exec`/`eval`/`open`**. You may
   **not** both "reuse `validate_code` as the safety check" and "import scanpy in the validated file" —
   pick shell-out, in writing.
3. **Gate-test rule (resolves the env-laundering paradox).** A synthesized/ingested skill's co-located
   pytest MUST assert the contract's postconditions on a **tiny synthetic JSON summary** (data-shape /
   obs-keys / layers), **WITHOUT** importing the heavy dep — the M11 `check_artifact` pattern ("validate
   AnnData shape *without importing scanpy*") is **mandated** for every gate test. This avoids the
   contradiction where a heavy-dep test either fails in the secret-stripped worktree (skill never lands)
   or is written to skip (`mutation_check` rejects it).
4. **External code is NEVER auto-merged AND NEVER auto-discovered.** Ingestion always produces a
   review-branch; `trust='external'` skills require an **explicit per-corpus human enable** before
   `discover_custom_skills` will load them. Adapters hard-fail loudly via `sc_method_environment_check`
   when deps are absent — they **never** degrade to a descriptive heuristic.
5. **Provenance must reach the reader, not just the writer.** `trust='external'` + `source_url` +
   `commit_sha` are written into `manifest.json` AND consumed: external skills are **excluded from
   `curator.recommend_curation` deferred→direct auto-promotion** (today it promotes on usage alone, with
   no trust check — verified), always require review-branch, and surface their provenance in the M7
   receipt. Without the read path, provenance is a dead field and an external skill silently auto-promotes
   to `direct` on usage.

## 9. Sequencing & Dependencies

```
M10 (tree) ───────┬────────────────────────────────────────┐
                  │                                         │
M11 (omics gate) ─┴──▶ M12 (paper→skill, ONE skill) ──▶ M13 (load-time safety) ──▶ M14 (GitHub ingestion, bulk)
                  │                                                                        
M10 ──────────────┴──▶ M15 (run-tree + online eval) ──▶ M16 (adversarial council, A/B-gated)
```

- **M10 and M11 are first and parallel** (orthogonal: pure-metadata tree vs. pure-decision reviewer).
  M10 is the **`first_milestone_id`** — the cheapest, lowest-regret foundation that M12/M13/M14 *and*
  the `navigate_skill_tree`/`classify_skill` filing of every acquired skill depend on. M11 is the safety
  spine that makes M12/M14 *trustworthy*; without it the corpus grows **wrong**.
- **The dependency-cycle is resolved explicitly:** M12 (synthesis) before M14 (ingestion). Prove the
  proposal→gate→classify loop on ONE non-shell skill with no env/shell complications, **then** harden the
  shell-adapter + env-gate path once the loop itself is trusted. M13 (load-time safety) sits between them
  because it is the precondition for loading *any* externally-authored code.
- **M15 before M16** so the online-eval number exists to A/B the adversarial council; M15 also measures
  the corpus-growth milestones, so it carries no hard dependency on M16.

## 10. Risks & Open Questions

1. **Synthesized-test shallowness (M12).** `generate_patch_for_proposal` does not verify test
   *relevance* (a vacuous `assert True` passes the gate). Mitigation: mandate the synthetic-fixture
   postcondition pattern (§7.3), ship review-branch-only, track accept rate, and never auto-merge analysis
   logic. Open: a relevance heuristic (does the test reference the contract's output keys?).
2. **`classify_skill` on the hot path (M10).** It is an LLM call during skill creation/ingestion; the
   deterministic `registry.search` fallback is mandatory for offline/unit-test and must be the path when
   the model is unavailable. Open: cache classifications keyed on `(name, description)` hash.
3. **M2 completion-gate regression (M11).** Wiring `review_methodology` into `completion.assess` changes
   the goal-acceptance gate that the green suite pins, and `completion.py` is under a `PROTECTED_PREFIX`.
   It MUST be additive + config-flagged + covered by tests proving no previously-accepted tabular goal
   starts block-failing. Confirm rollout is gated, not a default-on flip.
4. **Adapter import-whitelist vs. real omics deps (M13/M14).** Resolved as shell-out-only (§7.2); the
   open risk is adapter ergonomics — shelling every scanpy call through `local_exec` is verbose. Accept
   the verbosity; it is the price of one trust kernel.
5. **`MethodContract` fork risk.** Four personas independently declared the same dataclass. `method_contract.py`
   is the **single source of truth** (M11); M12/M14 import it. Build M11 first so nothing forks.
6. **Heavy-env reproducibility.** Shell-out adapters need scanpy/squidpy/cell2location/pySCENIC present
   to *run* (not to *gate*). `sc_method_environment_check` reports presence; M4 scheduler backends host
   the heavy steps; M7 receipts record the env. Open: a managed conda/container recipe per corpus.
7. **Declined-but-tempting (goal-e).** The crawler stays declined; revisit only after M10–M16 accumulate
   enough receipts + harness coverage to *measure* whether a frontier skill is good.

## 11. Explicit Non-Goals for v3.1-RC (cross-persona AVOIDs, enforced as constraints)

- **No MCP bridge / Effect-style ServiceLayer rewrite / async Scheduler+state-machine.** Infra-only
  refactors touching `PROTECTED_PREFIXES` with zero scientific capability; ingestion gives goal-b ≈90% of
  MCP's value through the already-hardened gate with no new execution surface. Defer MCP until a concrete
  external **service** (not a code repo) demands it.
- **No autonomous frontier daemon** (§6).
- **No deletion of the descriptive multiomics skills** — demote to `MULTIOMICS_PREVIEW` (a labeled
  "data-not-ready glance" the M1 DataProbe selects), and **never** let a heavy engine silently fall back
  to a heuristic when its deps are missing. Hard-fail loudly.
- **No second trust path.** Synthesis and ingestion are front-ends that emit a gated
  `{target_path, diff, test_commands}` proposal; never code that runs before the gate.
