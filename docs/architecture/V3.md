# Biobank Agent v3 Foundation

This page is the current shipping contract for the v3 foundation work. It
replaces the earlier "M1-M4 all complete" interpretation with a smaller,
verified scope that can be tested locally.

For the implementation backlog that remains after the verified foundation, see
`docs/architecture/V3_REMAINING_IMPLEMENTATION.md`.

## What Is Implemented

- Streaming runtime events through `biobank_agent.core.runtime.AsyncAgent`.
- Schema-first tool registration and `ToolHandler` wrappers for native and MCP
  tools.
- Plan-mode schema gates: invalid skill names, unsupported arguments, and
  missing required arguments block approval.
- Plan execution hard gates: skill exceptions, `is_error=True`, nested
  `result.error`, blocked DAG dependencies, and missing dual-report artifacts
  pause or fail the plan instead of counting as success.
- Full-data defaults for cohort, missingness, correlation, trajectory, and model
  workflows. The agent should not apply a second PII drop to already
  de-identified local data. Retry/reflexion logic may reduce computational
  knobs such as folds, repeats, `top_n`, or estimator counts, but it must not
  silently lower `sample_size` or `n_samples`; positive sampling remains an
  explicit user/operator choice.
- `generate_report(format="dual")` artifact verification for:
  `report.md`, `report_technical.md`, `report_nature.md`,
  `_report_with_css.md`, `_report_nature_with_css.md`, `report.html`, and
  `report_nature.html`.
- Textual TUI scaffold with plan, tool, disclosure, and log panels. Slash
  commands dispatch through the shared v3 command registry in the TUI, and plan
  events stream into the TUI panels. The progress panel now aggregates a
  long-running run dashboard with status, elapsed time, active tools, tool
  success/failure counters, phase summaries, and recent activity so long
  analyses do not look frozen. A run-detail panel also surfaces external
  planner/subagent status, pause reasons, actionable repair choices, review
  hook progress, report directories, and generated report artifacts. A
  worker/review queue panel now tracks concurrent main/external/subagent worker
  states and exposes F5-F9 keyboard actions for plan approval, resume, and
  repair choices without manually typing slash commands.
- Core slash commands, including session/status, plan/review/repair, external
  planner, MCP, replay, evolve, memory/pipeline, and debate commands, are
  registered through split modules under `biobank_agent.cli.commands`;
  `biobank_agent.cli_commands` remains as a compatibility re-export for older
  imports. Additional command modules can be injected with
  `BIOBANK_CLI_COMMAND_MODULES`.
- The legacy slash-command duplicate `if/elif` dispatcher has been removed;
  unknown commands now fall through to one registry-backed error path.
- Third-party slash command module packaging is documented in
  `docs/guides/CLI_COMMAND_PLUGINS.md`, with a runnable minimal example at
  `docs/examples/cli_command_plugin_demo.py`.
- The human-style live benchmark runner prints the run directory, queued
  workers, and per-worker completion summaries immediately so long runs do not
  look frozen.
- MCP manager for STDIO and HTTP/SSE-style JSON-RPC servers, including
  `/mcp-list`, `/mcp-start`, `/mcp-health`, `/mcp-call`, `/mcp-stop`, server
  status, startup retry/backoff, call-failure reconnect, health repair,
  restart counters, error tracking, project/env config path selection,
  structured HTTP auth headers, and legacy registry bridging.
- UKB/HPP/CKB bank adapter reference layer wired into cohort/model ICD-code
  paths for synthetic HPP/CKB fixtures; RAP-facing aliases such as `rap`,
  `ukb-rap`, and `ukb_rap` resolve to the same `RAPAdapter`.
  The `bank_data_probe` skill is agent-callable and checks the active
  DataManager, adapter identity, diagnosis filter, biomarker field resolution,
  full-data subject count, and RAP remote-ready metadata using aggregate output
  only. Trajectory default plans call it before cohort construction so bank
  wiring failures surface before model/report steps.
  The `bank_data_readiness` skill extends this into credential-gated
  UKB/HPP/CKB/RAP readiness checks: configured local paths are probed with
  aggregate metadata, missing credentials/paths are explicit `SKIPPED_*`
  statuses, and JSON/Markdown readiness artifacts are written without raw rows.
- Paper replication design cards and comparison artifacts that can link local
  table/figure outputs into final reports. `/replicate` now loads the proposed
  replication plan into Plan Review so the user can approve and execute it
  without manually copying JSON. DOI reads prefer repo-bundled
  `docs/related_works/*.pdf` matches before network fetching, so benchmark
  replication fixtures are deterministic. `paper_replication_compare` now emits
  numeric/figure acceptance gates for paper access, cohort counts, AUC,
  calibration ECE, feature importance, and table/figure artifact matching, and
  final reports render the acceptance verdict instead of hiding failed gates.
  The MILTON Nature Genetics paper fixture
  `docs/related_works/s41588-024-01898-1.pdf` is now a hard behavioral gold
  route: behavioral eval verifies the local DOI cache, PDF text extraction,
  replication plan, comparison prerequisites, guardrails, and dual-report
  dependency graph.
- Self-evolution risk classification, LOW generated-skill application path
  behind static allow-list plus ALWAYS_PASSES eval gate, MEDIUM generated
  proposal application only with an explicit TUI/host confirmation callback
  that displays risk, eval summary, and diff preview, MEDIUM decision audit
  rows under `reports/generated_skills/evolution_decisions.jsonl`, scheduled
  pattern-mining artifacts under `reports/eval/evolution`, and HIGH local
  branch/commit fallback (`pr_ready`) when a PR cannot be opened without
  credentials.
- Behavioral evals now include a hard `ALWAYS_PASSES` suite plus a soft
  `USUALLY_PASSES` suite. They can run through
  `biobank eval --suite behavioral --policy all|always|usually` or
  `python -m biobank_agent.eval.behavioral`, and both paths write
  `latest.json` plus JSONL pass-rate history under `reports/eval/behavioral`.
  `python -m biobank_agent.eval.scheduled` and
  `biobank eval --suite scheduled --policy all|always|usually` now compose
  behavioral eval plus evolution pattern mining into a scheduled manifest under
  `reports/eval/scheduled`, with a weekly GitHub Actions wrapper in
  `.github/workflows/biobank-scheduled-eval.yml`. The scheduled manifest also
  summarizes recent behavioral/evolution history counts and pass-rate trends.
- Strict live artifact auditing is available through
  `biobank eval --suite live_artifacts --run-dir <live-run> --enforce-gate`.
  It re-checks a human-style live run for dual-report artifacts, the frozen
  MILTON paper-replication acceptance gates, and the trajectory worker's
  tokenization plus world-model claim boundary. The latest strict audit passed
  against `reports/biobank_live_tests/full_after_scheduled_paper_gold/20260511_100909`.
- A full objective completion audit is available through
  `biobank eval --suite v3_completion --run-dir <live-run>`. It maps the v3
  objective to concrete evidence and reports `BLOCKED_EXTERNAL` for remaining
  credentialed items instead of allowing the project to claim completion from
  local tests alone.
- OpenTelemetry event-to-span bridge with low-cardinality metadata only, plus
  configurable `none`, `console`, and OTLP/HTTP exporters. Production collector
  policy is now enforced in code: `otel_policy=production` requires OTLP/HTTP,
  an explicit `/v1/traces` endpoint, and HTTPS/non-loopback transport unless an
  operator opts into a managed local sidecar.

## What Is Still Not v3.0 Complete

- Production Textual UI polish beyond the current long-run status,
  worker/review queue, and run-detail dashboards, especially screenshot-backed
  QA for large worker sets and deeper navigation of long repair histories.
- Real HPP/CKB/RAP data-path validation with credentialed datasets. The current
  HPP/CKB/RAP coverage proves the shipped DataManager -> cohort -> train_model
  path using fixtures and credential-gated aggregate probes, not private
  production datasets.
- MCP production matrix beyond the local STDIO and HTTP/SSE JSON-RPC contract:
  long-lived SSE streams, remote server packaging, and broader real-server
  compatibility still need hardening.
- Published-paper reproduction beyond the frozen MILTON fixture. The MILTON
  live route now runs paper -> StudySpec/plan -> execute -> comparison gates ->
  dual report and passes strict artifact audit; broader papers and true
  pixel/numeric diff remain future work when source tables/figures are
  extractable.
- Full self-evolution operations polish: screenshot-backed MEDIUM diff-review
  QA for very long patches, verified remote CI run history, and credentialed
  HIGH PR publishing.
- OpenTelemetry collector packaging examples for concrete deployment targets
  such as Jaeger, Tempo, or vendor OTLP collectors.

## Remaining Implementation Sequence

The remaining work should be implemented as separate release slices, not as one
large "M1-M4 complete" patch:

1. **CLI/TUI productization**: build richer Textual long-running task
   dashboards on top of the shared registry and event panels.
2. **Bank adapter data path**: keep the fixture parity and
   `bank_data_readiness` gates green, then run the same readiness artifact flow
   against real credentialed HPP/CKB/RAP datasets when those paths are
   available.
3. **MCP hardening**: add long-lived SSE stream lifecycle tests, packaging
   examples, and compatibility probes for real external MCP servers.
4. **Paper reproduction generalization**: keep the frozen MILTON strict live
   benchmark green, then add more published-paper fixtures and true
   numeric/pixel diffs where source tables/figures are extractable.
5. **Self-evolution closure**: harden long-diff Textual review QA, archive
   real remote CI run evidence, and finish HIGH risk credentialed PR publishing.
6. **Release engineering**: add collector packaging examples, SDK compatibility
   matrix, and v3.0 release notes after the above slices pass.

## Manual Plan Smoke Test

Start the CLI:

```bash
biobank
```

Then run:

```text
/plan Train the best feasible E11 model with model_type="auto"; inspect related fields and missingness; evaluate discrimination and calibration; run statistical_review, safety_check and world_model_audit; generate_report with format="dual" and exact output paths.
/plan-approve
```

Passing behavior:

- The plan is reviewed before execution.
- Invalid generated arguments block approval.
- Execution shows progress.
- Any failed required step pauses with repair choices.
- Completion is only valid if the report directory contains all dual-report
  artifacts listed above.

## MCP Smoke Test

Create `~/.biobank_agent/mcp_servers.json` pointing to a local test server or a
trusted MCP server. Then:

```text
/mcp-list
/mcp-start
/mcp-list
/mcp-health
/mcp-call server__tool {"query":"E11"}
/mcp-health --repair
/mcp-stop
```

The call result is recorded in session records with `source="mcp_call"` so it
can be audited by downstream reports or debugging tools.
